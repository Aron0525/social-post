# news-digest · 中文科技新闻推文生产与展示

一个围绕「AIHOT 每日科技新闻」的自动化内容管线：定时抓取新闻与实时热点榜、按三套写法转成推特长文、写入数据文件、由网页实时读取并分栏展示。仓库同时归档旷野体的写作规范与风格校验脚本。

三栏各自独立：新闻讲全、热点抢快、博眼球靠结构。判重按栏目分开，同一件事可以在三栏各写一条。

## 数据结构

`news-digest/posts.jsonl` 每行一条，字段固定：

| 字段 | 说明 |
| --- | --- |
| `round` | 场次标识，如 `2026-11-18 20时` |
| `title` | 标题，判重依据 |
| `st` | 状态，`new` 全新 / `overlap` 有重叠 / `same` 同一事件新进展 |
| `note` | 一句话定性，说明为什么值得看 |
| `text` | 正文，段落之间空行分隔 |
| `src` | 栏目，`v1` 新闻速览 / `v4` 讲解人 / `v2` 热点解构 / `v3` 博眼球 |

`src=v1` 取自速览写法，中位 269 字、4 段；`src=v4` 是讲解人写法，150 到 500 字、4 到 6 块、话头到判断四块、必须有"你"；`src=v2` 取热点解构写法，中位 84 字、2–4 个短块、首行 4–16 字；`src=v3` 取博眼球写法，60 到 150 字、3 到 5 块、首句是数字或反常识断言。

三栏各自独立：判重只在同一 `src` 内进行，同一件事可以在三栏各写一条，角度不同互不干扰。

## 服务端接口

`app/server.py` 默认监听 3000 端口，可用环境变量 `PORT` 覆盖。

| 路由 | 方法 | 用途 |
| --- | --- | --- |
| `/` | GET | 返回 `记录.html` |
| `/posts.jsonl` | GET | 返回全量数据 |
| `/list` | GET | 判重用的精简清单，含序号、场次、标题、状态、前 160 字摘要 |
| `/hot` | GET | 实时热点榜，五源抓取 + 跨榜聚类，见下 |
| `/corpus` | GET | 照抄模式清单，13 组原帖与新稿的段落结构、字数、手法对照 |
| `/count` | GET | 总条数 |
| `/append` | POST | 追加数据，需 `X-Sync-Token` 请求头；默认按标题判重，`?force=1` 强制写入 |

判重逻辑：去掉标点与数字后，公共前缀达 8 字，或汉字 bigram Jaccard 相似度 ≥ 0.55，即判为同一事件。判重按 src 分组，v1 写过的不影响 v2、v3 再写。

### 照抄模式

v2 和 v3 默认不自创结构，改为从 `/corpus` 清单里挑一条已验证的原帖，把段落数、每段句数、开口方式、收尾方式整体复制，只换内容。13 组样例见 `corpus/照抄格式对照表-13条.md`，执行规则见 `kuangye-writing/生成流程.md` 的 3.0 节。

令牌存放在 `news-digest/.sync_token`，已被 `.gitignore` 排除，不入库。

## 热点接口

`app/hotwatch.py` 并行抓五个源，合并后跨榜聚类，同一事件在多个榜出现会合并成一条并累计 `cross`：

| 源 | 内容 | 特点 |
| --- | --- | --- |
| 微博热搜 | 全网情绪出口 | 带热度值 |
| 抖音热榜 | 短视频侧注意力 | 热度值最直观 |
| 知乎热榜 | 中长文讨论 | 问题形式，适合提问引流 |
| 百度热榜 | 搜索侧关心 | 不带热度，按名次折算 |
| 华尔街见闻快讯 | 财经第一落点 | 带时间戳，最快 |

```bash
curl -s "http://127.0.0.1:3000/hot?topic=tech&limit=30"
```

参数：`limit` 条数（1–80，默认 30）、`topic=tech` 只看科技财经产业、`politics=1` 保留时政条目供人工核查。

返回字段：`title` 标题、`hot` 热度、`cross` 命中榜数、`sources` 命中的榜、`url` 链接。**排序先看 cross 再看热度**，四榜全中的才是真热点。

政治、外交、领导人行程、军事在抓取阶段打 `risk=politics` 剔除，不进入候选池。结果缓存 5 分钟。


## 写作规范

本地要求文件集中在 `kuangye-writing/`，规则优先级高于技能包自带说明：

- 句子长度必须有抖动，不允许整段同一节奏
- 开头直进事实，不写"最近有个新闻"这类铺垫
- 段与段之间空行，一条推文禁止整段糊成一坨
- 禁用引号书名号符号化的强调、禁用 emoji、禁用免责式收尾
- 同一事件再次出现时，必须有新事实才写，否则跳过

新增意见只写入 `意见记录.md`，不修改技能包本身，保证技能包与发行版一致。

## 版本管理约定

每次会话产生改动后，按以下顺序收尾：

1. `git add -A`（`.gitignore` 已排除令牌、缓存、会话数据）
2. 提交信息写清改了什么，例如 `新增 20时场次 6 条推文`
3. `git push origin main`

一键操作：

```bash
./sync.sh "提交说明"
```

未传说明时，脚本按当前时间自动生成。

远程仓库：https://github.com/Aron0525/social-post

服务端 `/append` 写成功后会自动在后台跑一次 `sync.sh`，所以定时任务产出的每一批推文都会自动形成一次提交并推送，无需人工干预。同步日志在 `news-digest/.git-sync.log`，已被忽略，不入库。

`github.com` 的解析在本环境常被指向不可达地址，`sync.sh` 推送失败时会自动调用 `fix_hosts.sh` 探测可用 IP 并写回 hosts，然后重试一次。手动执行顺序同样是先 `./fix_hosts.sh` 再 `./sync.sh`。
