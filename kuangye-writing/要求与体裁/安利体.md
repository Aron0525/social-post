# 安利体（工具 / 项目推广帖）· 用户补充格式

来源：Aron 2026-11-17 提供的样例帖（GitHub 自选股分析系统推广帖，原样附在文末）。
定位：kuangye-writing 的补充体裁。用于把一个工具、开源项目或资源写成可直接发布的推广帖。本体裁是长帖（一般 100-200 字），允许 emoji、箭头、链接，不套用 20-120 字短帖硬规则；但 stance 依然适用：口语、直接、无书面腔。

## 结构六段

1. **喊话开胃**：一句点名目标人群 + 真诚推荐。例：「喜欢炒股的兄弟，这个真心建议装一个」。人群要具体（喜欢 X 的兄弟 / 做自媒体的朋友），推荐词要带个人立场（真心建议 / 无脑冲前先试）。
2. **权威背书**：一个真实数字证明分量。GitHub 星数、下载量、用户量、榜单名次。**必须真实可查，用户提供或现场核实，不得编造，缺失标「待核实」。**
3. **一句定义**：它是什么 + 覆盖范围，一行说完。例：「一套用 AI 大模型做的自选股分析系统，A 股、港股、美股都能用」。范围可以列 3-5 项，用顿号串。
4. **使用方式**：怎么跑起来、结果送到哪里，突出省事。例：「每天自动跑一遍，把决策看板推到你的飞书、Telegram 或者邮箱」。
5. **它能帮你做什么👇**：3-4 条「→ 动词开头」短句，每条不超过 10 字，不写从句。例：→ 分析市场走势 / → 整理重要资讯 / → 跟踪个股表现 / → 自动生成投资分析报告。
6. **收尾三件套**：开源协议或成本亮点（MIT 开源、不用租服务器、免费）+ 链接放最后。

## 语气

口语、称呼亲近（兄弟 / 朋友们）、直接不端着。禁用书面腔，禁用「综上所述」「值得信赖」类套话。全帖不用冒号定义句，不用感叹号连发。

## 红线

- 数字（星数、用户量）必须用户提供或现场核实，缺失标「待核实」
- 链接必须真实可访问，写全不写缩略
- 不夸大功能，项目没做的功能不写
- 与 strict 短帖规则冲突处（emoji、箭头、链接、超 120 字）按本卡执行，输出不必跑 check_style

## 触发词

安利体 / 推广帖 / 安利一个工具 / 推荐项目 / 帮我写个安利 / promote post
