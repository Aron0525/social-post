# 热点选题规则

> 建立时间：2026-11-18 19:45
> 更新：2026-11-19 08:45 三栏职能重写，热点栏改由 `/hot` 监测榜单驱动
> 用途：网站三栏的选题与写法标准
> 结构依据：`写作范式/` 下三份范式（v2）、`结构库-v3.md` 十四条骨架（v3）

## 三个栏目怎么分

| 栏目 | 标记 | 选题从哪来 | 怎么写 | 字数 |
| --- | --- | --- | --- | --- |
| 新闻速览 | src=v1 | 行业新闻、财报、监管、技术发布 | 事实型，讲全讲透，五块结构，机制必须写清 | 80 到 900，分快讯、常规、深度三档 |
| 热点解构 | src=v2 | `/hot` 榜单，跨榜优先，当天 1 小时内 | 钩子型，三份范式，首行必须是钩子 | 30 到 250 |
| 博眼球 | src=v3 | 不限于新闻，结构本身即选题 | 从结构库十四条骨架里挑一条套上去 | 60 到 150 |

三栏各自独立运行，判重按栏目分组，同一件事可以在三栏各写一条，角度必须不同：

- v1 交代事实全貌和机制，读者能拿去做报告
- v2 给判断或抛问题，抢当天热度
- v3 只留一个印象，用数字对撞或反常识断言制造停顿

已在 v1 写过的事实，v2 不重复细节只挑一个点放大；v3 可以复用同一个数字，但必须换一个对立面来撞。**v3 也可以完全不看 v1 v2**，直接套结构写一件旧事或一个行业常识。

## 热点从哪来

不再靠人工回忆。本机服务有一个实时榜单接口，五源并行抓取、跨榜聚类、按题材过滤：

```bash
curl -s "http://127.0.0.1:3000/hot?topic=tech&limit=30"
```

返回里 `cross` 是命中榜数（4 就是四个榜同时在爆），`hot` 是热度值，`sources` 列出哪几个榜。**排序看 cross，其次看热度**，单榜条目只有在排名极靠前时才值得写。

政治、外交、领导人行程、军事在抓取阶段就被剔除，不会进入候选池，不用自己判断。


## 选题池

### 大公司，必须当天有新动作

| 类别 | 名单 |
| --- | --- |
| 海外模型 | OpenAI、谷歌、Anthropic、Meta、xAI、Mistral |
| 算力芯片 | 英伟达、AMD、台积电、博通、SK 海力士、三星 |
| 国内大厂 | 阿里、腾讯、字节、百度、华为、美团、比亚迪、小米、宁德时代 |
| 平台与工具 | 微软、苹果、亚马逊、Salesforce、GitHub |

不在名单里的公司也能选，条件是要有可比对的动作，比如融资金额、用户量、监管处罚这类硬事实。

### 社会热点，四个入口

1. 行业监管新规落地，比如备案要求、许可证发放、强制标准生效
2. 行业级拐点，比如某类岗位被替代、某个价格体系崩掉、某项标准被改写
3. 大规模公共事件，影响面在百万人以上
4. 有明确反差的对比，比如同一件事在两个国家、两代人的不同处理

## 三条硬标准，缺一条就不写

1. **当天有动作**。不能是旧闻回顾，不能是预测，要有具体的时间点或数字
2. **可核对**。至少两个独立信源，或一个官方一手发布
3. **有缺口**。要么反常识，要么数字刺眼，要么结论和主流说法不一样。三条都不占，只是平淡通报，退回 v1 写

## 不能选的

| 类型 | 原因 |
| --- | --- |
| 未证实的传闻、单一自媒体爆料 | 无法核对 |
| 纯八卦、私生活细节 | 与账号定位无关，且风险高 |
| 政治、外交、领导人行程、军事 | 一律不写。礼宾细节核实困难，评论区不可控，与账号定位无关 |
| 针对真实群体的贬损 | 违反范式 03 的风险边界 |
| 需要专业资质的建议，医疗、投资、法律 | 合规风险 |

## 结构怎么配

| 题材 | 用哪个范式 | 理由 |
| --- | --- | --- |
| 有反常识数字、有价差、有换算空间 | 01 钩子开路 | 钩子加兑现最顺 |
| 数据反常、现象矛盾、行业困惑 | 02 提问引流 | 讨论量最高 |
| 有现成观点可引、有认知落差 | 03 借壳反转 | 责任转移，反转有落差 |

## 入库字段

```json
{"round":"2026-11-18 20时场","title":"标题","st":"new","src":"v2","note":"范式01 冷知识开路，全新","text":"正文，段间用两个换行"}
```

`src` 只有 v1 和 v2 两个值，前端按它分栏。`note` 里必须写明用了哪份范式。
