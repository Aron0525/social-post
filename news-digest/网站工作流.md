# 新闻站工作流全解

> 本文档描述「推文记录」站点的完整生成链路：内容是怎么被发现的、怎么被写成四种栏目的、怎么通过质检写进库、又怎么自动同步到 GitHub。所有描述都以仓库内真实代码为准，不含推测。
>
> 站点：https://a88adb701fca5b5f7.app.workbuddy.host/?sharecode=Z7P36GJXP4
> 仓库：https://github.com/Aron0525/social-post

## 一、全景：一条流水线

```
每 2 小时（定时任务 15815371）
   │
   ▼
① 拉线上记录 /list ──────────── 判重：同事件三态标注（全新/部分重叠/不发）
   │
   ▼
② 拉实时热点 /hot ───────────── 五源抓取 + 跨榜聚类 + 题材过滤（服务端 hotwatch.py）
   │
   ▼
③ 多路联网搜索补素材 ─────────── 48 小时窗口，双信源要求
   │
   ▼
④ 写作（提示词驱动，四栏各有独立策略）
   │   v1 新闻速览（事实型，十四条例 + 三档长度）
   │   v4 讲解人（挂到 v1 条目下，问题→机制→读法）
   │   v2 热点解构（照抄语料库结构，钩子九型）
   │   v3 博眼球（照抄语料库结构，骨架 S01–S14）
   │   └─ 每条同步产出英文版 en_title / en_text
   │
   ▼
⑤ POST /append ─────────────── 服务端再判重一次（标题相似度），带 Token 鉴权
   │
   ▼
posts.jsonl（单行 JSONL 追加）
   │
   ├──► git 自动提交推送（sync.sh，后台线程，不阻塞接口）
   │
   └──► 前端 记录.html fetch posts.jsonl 渲染（三 tab + 讲解人内联 + 一键复制中英文）
```

站点本体是一个 Flask 服务（`app/server.py`，端口 3000），通过「发布为应用」挂到 workbuddy.host 域名。定时任务每 2 小时跑一次上面的提示词流程，把新条目 POST 进来；前端纯静态渲染，无登录。

## 二、组件清单

| 文件 | 角色 |
|---|---|
| `app/server.py` | Flask 服务：`/list` `/hot` `/corpus` `/append` `/audit` `/count`，含判重、Token 鉴权、git 自动同步 |
| `app/hotwatch.py` | 热点监测：五源并发抓取、跨榜聚类、题材过滤，5 分钟缓存 |
| `记录.html` | 前端单页：三 tab、讲解人内联挂载、筛选、体检按钮、中英文一键复制 |
| `posts.jsonl` | 唯一数据源，每行一条 JSON（四栏共用，靠 `src` 区分） |
| `corpus/corpus.json` | 语料库：12 组原帖与新稿的逐段对照，供 v2/v3 照抄结构 |
| `translate_en.py` | 存量条目批量补英文：codebuddy CLI 非交互翻译 + 哨兵标记防错配 |
| `prompt备份/` | 定时任务提示词新旧版本存档 + 变更记录 |
| `restart.sh` | 服务重启（精确杀 3000 端口进程，setsid 独立进程组拉起） |
| `/workspace/sync.sh` | 一键 commit + push，推失败自动修 hosts 重试 |
| `日志/` | 运行日志（36 小时运行日志等） |

数据字段（每条 JSONL）：

```
round     场次，如 "2026-11-25 16时场"
title     标题
st        三态：new 全新 / overlap 部分重叠 / same 与之前一模一样
note      一句话说明（新在哪 / 抄了哪条骨架 / 讲解角度）
text      中文正文（段间两个换行符）
src       栏目：v1 速览 / v2 热点解构 / v3 博眼球 / v4 讲解人
link      仅 v4：被讲解的那条 v1 标题原文
en_title  英文标题
en_text   英文正文
```

## 三、内容发现策略

### 3.1 热点监测（`/hot`，hotwatch.py）

- **五源并发抓取**：微博、知乎、抖音（经 codelife 聚合接口）、百度实时热搜、华尔街见闻快讯。榜单不给热度值时按名次折算（第一名约 500 万热度）。
- **跨榜聚类**：标题归一化后按汉字 bigram 相似度（阈值 0.55）合并同事件条目，合并后 `cross` = 命中榜数。**cross ≥ 2 视为真热点，优先写**；单榜条目只有排名极靠前才用。wscn 带时间戳，是抢一小时内的财经快讯通道。
- **题材过滤**：硬排除表命中即整条丢弃（领导人、外交、军事、会议等）；政策类（关税、制裁、出口管制）保留但打 `policy` 标记；`topic=tech` 时只保留科技财经产业关键词命中的条目。
- **排序分** = cross × 1e8 + 热度值，跨榜优先、热度其次。
- 结果缓存 5 分钟，抓取失败的源单独记录，不影响其他源。

### 3.2 判重（两层）

第一层在提示词里：任务必须真的拉 `/list`（全量已有条目 + 前 160 字摘要），**按事件判重而非按文字**，同一事件换角度、换数字、换标题都算同一条。判重按栏目分组——同一事件 v1 写过，不妨碍 v4 换个人视角再写。三态：

| 判定 | 条件 | 处理 |
|---|---|---|
| A 全新 | 列表里没有 | 正常生成，标 ✅ |
| B 不发 | 已有且无新事实 | 不生成，只在报告里一句话说明 |
| C 部分重叠 | 已有但有实质新进展 | 生成，标 ⚠️，note 写明新在哪 |

第二层在服务端：`/append` 收到数据后按标题算相似度（8 字以上公共前缀，或 bigram Jaccard ≥ 0.55），同 src 内命中即拒收，返回 `skipped_duplicate`。确认真有新进展才允许 `?force=1` 强推。

## 四、四栏写作策略

### 4.1 v1 新闻速览——事实型主稿（80–900 字）

目标是"读起来像人在手机上随手写的"。核心纪律：

- **句长要抖**：至少一句 10 字以内、一句 30 字以上，全篇 20 字上下匀速 = 失败。
- **开头直接进事实**，禁止"最近 / 随着 / 在背景下 / 先说结论"。
- **免责尾巴一律不留**：据说、待核实、我没核过之类整句删掉，宁少一句不退让。
- **结尾停在事实/数字/动作上**，不总结不升华不问"你怎么看"。
- **黑名单词**：总之、综上、值得注意的是、本质上、赋能、闭环、抓手……
- **数字照抄原始口径**，不换算不加"约"，查不到就不写。
- 长度三档：快讯 80–200 / 常规 250–450（含一个反常识点）/ 深度 500–900。
- 深度稿走五块结构：结论先行 → 事实主体 → 机制拆解 → 反面代价 → 观察点。第三块是分水岭——"把机制块删掉这篇还成立吗？成立说明没写透"。

### 4.2 v4 讲解人——挂在速览下的"人话版"（150–500 字）

不是独立栏目，靠 `link` 字段挂到对应 v1 条目下方展示。与 v1 讲同一件事但**换一个人说**：结构是"话头 → 背景 → 机制 → 我的读法"，因果是讲出来的。

- 硬性身份标记：全文"你"至少出现 2 次；第一块不能是结论，要留疑问或真实反应。
- **反 AI 元话语**（D1.2 规范）：六个禁用结构——标签+冒号、标签+逗号切句、预告思考动作（"我试着拆成三层"）、自问自答（"要是让我下一个判断"）、冒号引清单、段首模板轮转。
- **删标签检验法**：把"我的理解是/我的看法是/我试着"逐个删掉再读，删完还通顺说明那是贴标签，直接删；删完散架说明内容依赖标签，重写成完整句。
- 判据："我"后面接抽象认知名词（理解/读法/判断）是 AI 标签；接具体动作和情绪（愣了一下、翻了一遍、押不出来）才是真人。
- 数字必须来自 v1 已核实的双信源，不许另编。

### 4.3 v2 热点解构——追当天，快（30–250 字）

- 选题只从 `/hot` 榜单挑：cross ≥ 2 优先，单榜须前五。核心指标是**快**，宁可角度刁。
- **默认照抄模式**：先读 `/corpus` 语料库（12 组原帖与新稿逐段对照），挑最贴合的一条，**段落数、每段句数、开口方式、收尾方式、标点习惯全部复制**，只换内容。note 里写明抄的编号（如"照抄 X20"）。语料库读不到才退回自创范式。
- 钩子结构：首行 2–16 字以逗号/冒号收尾，从九型选（冷知识/暴论/真理/建议/白嫖/扎心提问/人群分类/示弱求教/名人引用）。

### 4.4 v3 博眼球——话术结构库（60–150 字）

- 与前三栏完全独立，可以不写新闻，写旧事、行业常识、精确到荒谬的细节；唯一硬要求是数字、公司、时间必须真实。
- 同样默认照抄语料库；退回自创时从 **S01–S14 骨架**选一条（数字对撞、悬念收尾、三级推演、单点爆破、反常识断言、先夸后贬、借壳反转……），**不许和上一轮用同一条**，note 写明编号。
- S03 和 S12 一个月内各不超过两条（易写成招募话术）。写完自问：读者读完最后一句拿到新事实了吗？没有就换骨架重写。

### 4.5 排版硬约束（四栏通用）

- **汉字与数字之间不留空格**（"11月20日"不是"11 月 20 日"）——全库最普遍的 AI 痕迹，曾一次清出 152 条。
- 汉字与英文专有名词之间的空格要留（"在 Anthropic 上班"），两者区分处理。
- 中文句子里不许夹英文普通词（rules → 规矩），专有名词和技术通用词除外。
- 不用引号、感叹号、破折号、省略号、emoji、加粗；逗号用中文逗号。

### 4.6 英文版（en_title / en_text）

两条生产线：

1. **任务内联**（新提示词第 4.7 步）：四栏每条生成时直接带英文，九条要求——语气跟原文（口语就口语）、段落结构逐段一致、数字专名照抄不换算、梗和反差保住、专有名词保留惯用写法、不增不减、长度不卡、v4 保住第二人称 you、写完自检。
2. **存量补齐**（`translate_en.py`）：对历史无英文的条目批量翻译。经 codebuddy CLI 非交互调用，防错配三件套——
   - **哨兵标记** `[[M0001]]`：每条标题前塞标记，按标记配对返回结果，不信任模型自报的顺序；
   - **check_pair 校验**：段落数一致、百分比/年份硬校验、数字密度、专名覆盖率，不过关逐条串行补跑；
   - **全局行号 id + 每批落盘**：防跨批次撞键（曾导致 75 条错配全部作废重做），且被沙箱休眠杀掉也不丢已完成批次。

前端展示仍是中文，英文只供一键复制（「复制英文」按钮）和点「英文」展开预览。

## 五、质量保障

### 5.1 `/audit` 全库体检（前端「体检」按钮）

- **v4 专查**：六种元话语结构、标签+冒号/逗号、"你"少于两次。
- **四栏通用**：中数空格（英文型号后紧跟的空格不算，如 `Mate X8 发布会`）、混排英文杂质词、测试残留。
- 任何一轮产出后都能一键核对，目标恒为 0 违规。

### 5.2 写入即备份

`/append` 成功后由后台线程自动执行 `sync.sh` commit + push，不阻塞接口响应；push 失败自动修 hosts 重试一次。令牌（`.sync_token`）不入库。

### 5.3 运维

| 场景 | 处理 |
|---|---|
| 服务挂/改了代码 | `bash restart.sh`（精确杀 3000 进程，setsid 拉起，15 秒就绪探测） |
| 沙箱休眠杀掉长任务 | 长任务全部设计为**逐批落盘**，恢复后续跑即可 |
| 批量翻译中断 | `python3 translate_en.py`（自动跳过已有英文的条目，断点续跑） |
| 体检出违规 | 按 `/audit` 返回逐条修文案 |
| push 失败 | sync.sh 内置 fix_hosts 重试；再失败看 `.git-sync.log` |

## 六、已知边界

- 定时任务运行在隔离沙箱，禁止本地文件读写，全部走 HTTP 接口——所以接口就是数据唯一入口。
- `posts.jsonl` 无自增 id，批量翻译用 `(src, round, title)` 做行键合并，跨场次同名条目靠场次区分。
- 沙箱休眠会终止后台进程：服务由平台拉起，长任务需人工续跑。
- 热点接口的政治过滤是关键词表 + 软标记，兜底能力有限；提示词层要求任务遇到时政题材直接跳过，双保险。
